# Grouping does not travel in the archive

[0032](0032-archive-preserves-inputs-not-derived-state.md) put transaction grouping
in tier 1 because no rule existed that could reconstruct it.
[0041](0041-server-owns-transaction-grouping.md) built that rule, and it reads
stored data and fetches nothing, which is 0032's definition of tier 3 -- cheap, and
excluded.

**The archive carries postings, not groups.** A `TxWindow` holds its postings
directly, and the partition is recomputed on import from the evidence the postings
carry ([0048](0048-correlations-declare-their-own-semantics.md)).

The group level does not shrink, it goes. Every other aggregate root in the format
carries fields of its own -- an instrument has its identifier, asset class and
coverage, a statement its account and date -- while a tx group has neither an id nor
a timestamp, both being generated by the importing instance. So the tx group is a
level whose entire payload is the partition, and once the partition is derived there
is nothing left in it. [0035](0035-archive-nests-by-aggregate-root.md) admits a
level only for what cannot vary between rows below it; a level with no fields at all
never met that test, and only looked like it did while the partition was data.

The upload format follows, because it is the same message. One schema in both
directions is what [0034](0034-archive-format-is-its-own-proto-package.md) is for,
and a nested export beside a flat upload would need a second reader.

## Considered: the archive records a partition the importer honours

Keeping the group level as a record of the last accepted partition survives an
engine regression and restores data ingested before evidence was captured, which
regrouping does not.

It was rejected because it reinstates exactly what 0041 removed: two things that
decide the partition, one of them a file. The importing server would either honour
the file and hold data it cannot explain from evidence, or regroup and silently
disagree with what the file says. Neither is better than not carrying it, and the
first is the two-rule-sets outcome 0041 turned down when the second rule set was a
converter.

**A source-asserted correlation is not that alternative.** A correlation is an
identifier with declared comparison semantics, and the importer regroups from it
like any other evidence -- so there is still exactly one thing deciding the
partition. That the highest-precedence pass usually reproduces what the source
intended is a property of the evidence being good, not of the file being obeyed.

## Consequences

**Routed residuals are not exported.** A residual carries no correlation evidence of
its own, so once the importer regroups it has nothing to say which postings it
belongs with. It joins the synthetic `INITIALIZE` postings in 0032's tier 3 and is
routed fresh after the grouping pass.

**A human assertion is still tier 1.** A hand-made grouping or transfer match is an
input, not a partition, and an archive that drops the partition still has to carry
it. It travels as the assertion it is, alongside the postings, not as a shape imposed
on them.

**The archive carries the declared transaction type, not the resolved one.**
[0044](0044-tx-type-is-declared-and-resolved.md) splits the type into what the source
said and what grouping concluded. The second is derived from the partition this ADR
refuses to carry, so exporting it would ship a conclusion the importing server cannot
justify and may contradict as soon as it regroups. It is tier 3 for the same reason
the routed residuals are, and is recomputed by the grouping pass on import.
