Retire the standard transaction CSV and have converters produce archive messages
instead.

## Motivation

The standard transaction CSV is the most heavily used format in the repository
and the one with the least reason to be a CSV. It is machine-written by
converters and machine-parsed by client/lib/csv/standard.ts; no human reads it
and no pipeline consumes it downstream. Its claim is inertia.

Meanwhile it is lossy against its own API. `Tx.identifier_hints` is a repeated
`InstrumentIdentifier` but the file carries at most one hint per row. Grouping
travels as `group_ref`, an opaque key scoped to one upload that exists only
because rows cannot nest. `broker`, the period and `share_count_basis` are
carried by the upload request rather than the file, so an upload is not
self-describing.

## Design

Converters already return `StandardParseResult` -- an envelope of txs, period
bounds and `share_count_basis` -- rather than CSV text, so the object model is
most of the way there. What changes is which serialiser the file path uses, and
that groups become structural rather than keyed.

Consequences that fall out:

- `group_ref` disappears. Postings nest inside their group.
- A posting can carry several identifier hints.
- `broker`, period and `share_count_basis` move into the file.
- The paired-presence validation that `exchange` requires `exchange_type` and
  back goes with the columns; `identifier_type` already says whether the domain
  is a MIC or an OpenFIGI code, so `exchange_type` was redundant.

Retire client/lib/csv/standard.ts and its tests, and the transaction CSV section
of docs/spec/csv-format.md, which is then empty and can be deleted.

## Downstream

The conversion is wider than the repository. `local/scripts/convert-fidelity.py`,
`convert-ibkr.py` and `convert-schwab.py` write these column names, as do the
masters in `local/standard-format/`; those are regenerated by re-running the
scripts. Three e2e fixtures carry the old headers:
e2e/fixtures/split-txs.csv, e2e/fixtures/standard-3-stocks.csv and
e2e/fixtures/fetch-blocks-stocks.csv.

The browser extension imports the same converters through its tsconfig path
alias and is affected by whatever they return, so it moves with them.

The broker-file upload UI is unaffected: converters still read Fidelity CSV,
IBKR OFX and Schwab CSV, which are the brokers' own formats. Only the standard
format in between is replaced.
